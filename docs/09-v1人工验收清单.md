# 有迹（YouTrace）v1.0.7 人工验收清单

本清单用于完成自动测试无法替代的 Windows 原生与用户体验验收。请只使用测试工作区，
逐项记录结果和证据；所有必需项通过后，整体版本才能从 `PREPARED` 进入 `VERIFIED`，
再由你确认是否进入 `ACCEPTED`。

## 1. 开始前准备

请准备以下环境和材料：

- 一台没有 Node.js、npm 和项目源码的 Windows 10/11 x64 测试环境；
- 普通用户账户，不使用管理员权限运行有迹；
- `YouTrace-1.0.7-Setup.exe`、`YouTrace-1.0.7-Portable.exe` 和
  `SHA256SUMS.txt`；
- 一个可删除的本地测试工作区；
- 一个可移动磁盘或可安全断开的测试卷；
- 两台不同缩放比例的显示器；如果没有，请把对应项目记为 `BLOCKED`，不要写成通过；
- Windows Narrator（讲述人）和系统“减少动画”设置。

不要使用真实工作区执行断盘、空间不足、权限修改、恢复或卸载测试。先记录测试环境：

## 2. 验证安装、便携版和离线使用

1. 断开测试环境的网络连接。
2. 运行安装版，选择安装目录并启动有迹。
3. 创建测试工作区，创建一个项目、一项任务和一条备忘。
4. 明确退出应用，再次启动并确认数据仍存在。
5. 卸载安装版，确认外部测试工作区仍存在。
6. 运行便携版，创建另一个工作区并完成相同的保存与重启检查。

验收结果：

- [ ] 安装版无需开发环境即可安装和启动。
- [ ] 便携版无需安装即可启动。
- [ ] 断网时核心功能可用。
- [ ] 普通用户权限足够，应用不要求管理员权限。
- [ ] 卸载不会删除用户选择的外部工作区。

## 3. 验证 Windows 原生交互

1. 在首次启动页和设置页打开文件夹选择器，确认标题、当前目录和按钮文字可理解。
2. 在数据中心打开工作区目录，确认资源管理器定位到当前工作区。
3. 导入一个测试证据文件，再从应用中打开该文件。
4. 添加一个 `https://` 证据链接，再从应用中用默认浏览器打开。
5. 创建一个一分钟内到期的提醒，确认系统通知显示“有迹”名称和正确图标。
6. 单击系统通知，确认主窗口恢复、置前并定位到相关内容。

验收结果：

- [ ] 文件夹选择器行为正确。
- [ ] 资源管理器能打开当前工作区。
- [ ] 证据文件能由关联程序打开。
- [ ] 安全网页链接能由默认浏览器打开。
- [ ] 系统通知的名称、图标和内容正确。
- [ ] 单击通知能恢复并聚焦有迹。

## 4. 验证托盘、退出和活动计时

1. 开始一段任务计时。
2. 关闭主窗口，确认窗口隐藏到托盘，计时仍继续。
3. 从托盘恢复窗口，确认窗口置前且计时状态没有丢失。
4. 从托盘选择退出，在活动计时提示中选择“取消退出”，确认应用继续运行。
5. 再次选择退出并选择“保留未结束会话”，确认进程退出。
6. 重启应用，确认会话显示为暂停，且退出后的离线时间没有计入努力。
7. 恢复并停止该会话，保存结果。
8. 新建另一段计时，从托盘退出并选择“保存到当前时刻并停止”。
9. 重启应用，确认已记录的投入仍存在。
10. 新建一段计时，等待至少 20 秒后使用任务管理器结束有迹进程，再重新启动。
11. 确认应用显示异常中断恢复页、可靠记录时间合理，且可以选择保留暂停、继续或按实际时间停止。
12. 在快速备忘或复盘中输入尚未保存的长文本，等待 2 秒后再次用任务管理器结束进程。
13. 重启后确认可以恢复或明确放弃未提交文字，正常保存后不再重复提示。
14. 在设置中选择“直接退出程序”并保存，关闭主窗口，确认程序不再留在托盘。
15. 重新打开程序，改回“最小化到托盘”并保存，确认关闭窗口后托盘图标可见。

验收结果：

- [ ] 关闭窗口默认隐藏到托盘。
- [ ] 托盘恢复和双击行为正确。
- [ ] “取消退出”不会结束进程或丢失计时。
- [ ] “保留未结束会话”会暂停会话，不计算离线时间。
- [ ] “保存到当前时刻并停止”会保存投入并退出。
- [ ] 异常结束进程后，离线时间不计入努力，并由用户确认恢复方式。
- [ ] 快速备忘和复盘的未提交长文本可以恢复，正常保存后恢复提示消失。
- [ ] 托盘“退出”能真正结束全部有迹进程。
- [ ] 两种关闭行为都与设置一致，开发版和发布包托盘图标均可见。

## 5. 验证睡眠、静默时间和提醒汇总

1. 设置一段覆盖当前时间的静默时间。
2. 创建会在静默时间内到期的提醒，确认它不会立即重复弹出。
3. 等待静默时间结束，确认提醒按设置延后或进入一次汇总。
4. 创建另一个短时提醒，让 Windows 进入睡眠并跨过提醒时间。
5. 唤醒 Windows，确认同一提醒不会重复触发。
6. 明确退出应用并跨过一个提醒时间，再启动应用。
7. 确认应用只显示去重后的错过提醒汇总，不连续弹出大量通知。

验收结果：

- [ ] 静默时间内不重复弹出提醒。
- [ ] 静默结束后的延后或汇总符合设置。
- [ ] 睡眠恢复后同一提醒只处理一次。
- [ ] 离线重启后只显示去重汇总。

证据或问题记录：

## 6. 验证移动介质断开与重连

1. 在可移动介质上创建一个测试工作区。
2. 打开一条尚未保存的备忘草稿。
3. 安全断开介质，等待应用显示“工作区不可用”。
4. 尝试执行保存操作，确认应用阻止写入并保留可复制的草稿。
5. 在原路径创建同名空目录并尝试重连，确认应用拒绝把它当作原工作区。
6. 重新连接原介质，选择包含原工作区标识和数据库的完整目录。
7. 确认应用恢复连接，草稿仍在，并可正常保存。

验收结果：

- [ ] 介质失联后应用停止写入。
- [ ] 未保存草稿仍可查看和复制。
- [ ] 同路径空目录或其他工作区不能冒充原工作区。
- [ ] 原工作区重新出现后可以安全重连。
- [ ] 重连后原数据完整，新的写入成功。

## 7. 验证迁移失败保护

仅在独立测试卷、虚拟磁盘或专用测试目录中执行本节。不要填满系统盘，也不要修改真实工作区
的权限。

1. 创建包含项目、任务、努力和证据文件的测试工作区。
2. 把目标设为剩余空间小于迁移所需空间的测试卷，执行迁移。
3. 确认应用报告空间不足，仍使用源工作区，源数据可读写。
4. 把另一个空目标目录设为当前用户不可写，执行迁移。
5. 确认应用报告目标不可写，仍使用源工作区，源数据可读写。
6. 恢复测试目录权限，并确认失败目标没有被当作当前工作区。

验收结果：

- [ ] 空间不足时源工作区不切换、不丢数据。
- [ ] 目标不可写时源工作区不切换、不丢数据。
- [ ] 错误提示说明如何释放空间、修复权限或改选目录。
- [ ] 迁移失败报告能说明源路径、目标路径和失败原因。

### 7.1 验证备份空间与数据库损坏恢复

本节只允许使用可丢弃的测试工作区。不要修改真实工作区数据库。

1. 在设置页检查备份占用、下一份预计空间和磁盘可用空间是否清晰。
2. 确认默认策略为每日 7 份、每周 4 份、每月 6 份，并可修改保存。
3. 创建手动备份并明确退出有迹。
4. 先把测试工作区的 `database\youtrace.sqlite3` 复制到工作区外留作临时保险。
5. 用无效文本覆盖测试工作区中的 `youtrace.sqlite3`，然后启动有迹。
6. 确认程序不进入普通工作台，并显示损坏副本、恢复报告、受影响范围和独立恢复候选。
7. 打开恢复报告，确认原工作区路径、损坏副本和候选路径可辨认。
8. 选择“确认切换到恢复副本”，确认备份时间点的数据可读写。
9. 返回原测试工作区，确认被覆盖的损坏数据库和原备份仍然存在，没有被自动删除。

验收结果：

- [ ] 设置页显示备份占用和下一份预计空间。
- [ ] 日/周/月分层保留策略可理解、可保存。
- [ ] 数据库损坏后停止危险写入并保留只读副本。
- [ ] 只有明确确认后才切换到独立恢复副本。
- [ ] 原损坏数据库和原备份不会被自动删除。

证据或问题记录：

## 8. 验证缩放、多显示器和窗口行为

1. 分别在 100%、125%、150% 和 200% 系统缩放下启动应用。
2. 在每档缩放下检查全部主导航、备忘输入、设置表单和对话框。
3. 从四条边和四个角调整窗口尺寸，确认最小尺寸仍保留核心导航。
4. 使用 Windows 贴靠、最大化、还原和最小化。
5. 在两台不同缩放比例的显示器之间移动窗口。
6. 在副屏关闭到托盘，再从托盘和通知恢复窗口。
7. 确认窗口始终位于可见工作区，文字和控件没有裁切或重叠。

验收结果：

- [ ] 四档缩放下核心内容都可到达。
- [ ] 输入框边界清晰，普通表单文字不显得过小。
- [ ] 四边四角缩放与最小尺寸正确。
- [ ] 贴靠、最大化、还原和最小化正确。
- [ ] 跨不同 DPI 显示器移动后布局和窗口位置正确。
- [ ] 从托盘或通知恢复后窗口可见并获得焦点。

## 9. 验证键盘、讲述人和减少动画

1. 不使用鼠标，只用 `Tab`、`Shift+Tab`、`Enter`、`Space` 和 `Esc` 完成创建任务、
   写备忘、打开设置和关闭对话框。
2. 打开 Windows Narrator，重复核心流程。
3. 确认讲述人能读出控件名称、角色、状态、错误和只读提示。
4. 打开 Windows“减少动画”，切换页面、打开菜单和对话框。
5. 检查浅色与深色主题中的焦点轮廓、正文、辅助文字和输入边界。

验收结果：

- [ ] 键盘可到达所有核心控件，焦点顺序合理。
- [ ] 对话框会限制焦点，`Esc` 行为符合预期。
- [ ] 讲述人能识别名称、角色、状态和错误。
- [ ] 减少动画开启后没有位移或缩放动画。
- [ ] 浅色和深色主题下焦点与文字可辨识。

## 10. 完成用户验收

在前述必需项通过后，使用同一个测试工作区完成以下连续流程：

- [ ] 从项目和目标创建课程或长期计划，并完成一项任务。
- [ ] 用标签连接项目、任务、备忘、努力和成果，再检查聚合与筛选。
- [ ] 完成计时、补录、更正、成果验证和复盘调整。
- [ ] 通过点击和拖拽分别添加真实附件，确认工作区内出现副本且原文件仍在原处。
- [ ] 归档一条已转换的备忘后永久删除，确认原文不可恢复且转换对象和附件仍保留。
- [ ] 完成复盘后确认正文只读、“编辑复盘”和“删除复盘”字号一致，编辑后可保存修改。
- [ ] 创建备份，迁移工作区，并确认源目录保留。
- [ ] 确认首页信息密度、浅色/深色主题、文字大小和整体操作体验可接受。

# 有迹（YouTrace）项目文档索引

本目录定义有迹 Windows 桌面程序的 v1 产品范围、领域逻辑、技术架构、工作区规则和验收标准。开发、测试和范围变更都应从本页进入，并以这些文档的交叉约束为准。

## 1. 产品定位

有迹是一款面向个人的本地综合执行管理程序。它围绕“让每一次努力都有迹可循”建立从目标、计划、执行、努力记录、成果验证到复盘调整的完整闭环。

v1 是可长期使用的完整本地版本，不是只验证界面的功能样机。它覆盖学习、健身、编程、读书和一般个人项目，不包含 AI 辅助、云端账户和多人协作。

## 3. 决策优先级

文档出现歧义时，按下面的顺序确定结果。

1. 以 [产品需求文档（PRD）](01-产品需求文档-PRD.md) 的产品边界为最高依据。
2. 以 [领域模型与逻辑关系](03-领域模型与逻辑关系.md) 的业务不变量为数据行为依据。
3. 以 [工作区与数据安全](05-工作区与数据安全.md) 的数据安全约束为文件操作依据。
4. 以 [技术架构](04-技术架构.md) 的模块边界为实现依据。
5. 以 [v1 验收标准](06-v1验收标准.md) 判断功能是否可以宣布完成。

如果两个要求仍然冲突，应先更新文档并记录决策，再修改代码。实现不能静默改变需求。

## 4. v1 已确认决策

下面的决策构成第一版基线。

- 产品名为“有迹”，英文名为“YouTrace”。
- 目标平台为 Windows，程序形态为 Electron 桌面应用。
- v1 界面仅提供简体中文。
- 程序使用不透明的自绘标题栏和窗口控制，不显示原生 Windows 标题栏与边框。
- 视觉采用“冷静工作台 + 轨迹线”主题，提供配套的浅色与深色模式。
- 主窗口关闭后默认隐藏到系统托盘，以保证计时和提醒继续运行；用户明确退出后停止后台任务。
- v1 包含计划、执行、进度、倒计时、备忘、标签、复盘、数据管理等完整功能。
- 每门课程同时支持等权进度和工作量进度。
- 每个任务支持难度、优先级、预计时间、实际时间和截止日期。
- 标签可选、可多选、可自定义，并适用于所有主要业务对象。
- 用户选择一个工作区根目录，业务数据和业务文件全部保存在该目录下。
- 程序默认离线运行，不依赖远程服务器。
- v1 不包含 AI 辅助、社交排名、云端账户和多人协作。

## 5. 文档状态

规范文档已完成，v1.0.4 实现、真实 Electron 自动测试和本机打包证据见
[v1 实现与验收报告](07-v1实现与验收报告.md)。整体发布状态仍为 `PREPARED`：
自动化范围已经验证，但干净 Windows、真实移动盘、混合 DPI 多显示器、Narrator、原生通知与
用户体验仍需按 [v1 人工验收清单](09-v1人工验收清单.md) 检查，因此不能提前标记为
`VERIFIED` 或 `ACCEPTED`。

后续使用下面的状态区分文档和实现证据。

| 状态 | 含义 |
|---|---|
| `PREPARED` | 已形成需求、设计、代码或测试材料，但尚未实际验证 |
| `VERIFIED` | 已通过对应层级的检查或真实运行验证 |
| `ACCEPTED` | 已由产品负责人或用户正式确认结果 |

“文档写完”“程序能启动”和“功能正确”是三个不同结论。只有 [v1 验收标准](06-v1验收标准.md) 中的对应证据齐全，功能才能进入 `VERIFIED`。

## 6. 统一术语

这些术语在全部文档和代码中保持一致。

| 术语 | 定义 |
|---|---|
| 工作区 | 用户选择的有迹数据根目录及其中的全部业务数据 |
| 领域 | 学习、健身、编程、读书等长期关注范围 |
| 项目 | 为一段明确结果组织目标、任务和记录的容器 |
| 目标 | 有成功标准和时间边界的期望结果 |
| 里程碑 | 目标中的阶段性可验证结果，例如教材章节 |
| 任务 | 可执行、可完成的一次性行动 |
| 习惯 | 按规则重复发生并逐次记录的行动 |
| 指标 | 以数值和单位累计或测量的目标 |
| 努力记录 | 一次真实投入的时间、过程、困难和下一步 |
| 成果证据 | 支持“已完成、已验证或已认可”的文件、链接、成绩或反馈 |
| 掌握度 | 对知识理解和运用程度的独立衡量，不等于执行进度 |
| 标签 | 跨模块关联、筛选和统计对象的可选分类 |

## 7. 文档维护规则

项目演进时应保持需求、逻辑、实现和验收之间可追踪。

- 新增或删除 v1 功能时，先修改 PRD，再更新功能设计和验收标准。
- 修改实体关系、进度计算或删除规则时，同步更新领域模型。
- 修改根目录、附件、备份或迁移行为时，同步更新数据安全文档。
- 修改 Electron 进程、IPC 或存储边界时，同步更新技术架构。
- 文档中的相对链接必须保持有效，不能留下孤立文档。

## 8. 最终规划审查记录

2026-07-30 完成发布前最后一轮规划审查。本轮未改变 v1 功能范围，也未引入应用升级、云端、AI 或协作能力；仅补齐提醒后台生命周期、中文全文检索、日期时间语义、自绘窗口边界和相应验收证据。

当前七份规范文档之间没有已知的阻断级冲突。规划仍为 `PREPARED`，技术选型、性能、自绘窗口行为和打包结果必须经过真实 Electron 实现与 [v1 验收标准](06-v1验收标准.md) 后才能进入 `VERIFIED`。

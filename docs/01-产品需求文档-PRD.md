# 有迹（YouTrace）v1 产品需求文档

本文定义有迹 v1 的产品目标、完整范围、核心用户流程和质量要求。开发团队应在不引入 AI、云端账户和多人协作的前提下，交付一款可安装、可离线、可迁移且可长期保存努力证据的 Windows Electron 程序。

## 1. 文档信息

本文是 v1 产品范围的权威来源，具体交互见 [功能设计](02-功能设计.md)，实现边界见 [技术架构](04-技术架构.md)。

| 项目 | 内容 |
|---|---|
| 产品名称 | 有迹（YouTrace） |
| 产品标语 | 让每一次努力都有迹可循 |
| 目标版本 | v1 |
| 目标平台 | Windows 桌面端 |
| 程序形态 | Electron 本地应用 |
| 主要用户 | 希望看见真实投入、成果和进度的个人用户 |
| 数据策略 | 本地优先、离线可用、根目录归用户控制 |
| 界面语言 | v1 仅支持简体中文 |
| 文档状态 | `PREPARED` |

## 2. 产品问题

传统任务工具通常只记录“有没有打勾”，无法解释用户花了多少时间、留下了什么成果、是否真正掌握内容，以及当前速度能否按期完成。有迹通过永久努力账本、成果证据和真实进度模型解决这一问题。

产品需要持续回答四个问题：

- 今天最应该做什么？
- 时间和精力实际花在了哪里？
- 哪些目标正在产生真实成果？
- 按当前速度能否在期限前完成？

## 3. 产品目标

v1 需要形成一个可以独立运行的完整闭环。

- 让用户把长期目标拆分为项目、里程碑和可执行任务。
- 让每次专注、学习、训练和产出都形成可回看的努力记录。
- 同时展示执行进度、工作量进度、掌握度和验证状态。
- 用倒计时、时间容量和复盘帮助用户及时调整计划。
- 让备忘、标签、成果和附件跨模块关联，而不是成为信息孤岛。
- 让用户通过复制工作区根目录完成备份和迁移。

## 4. 产品原则

这些原则用于处理功能冲突和设计取舍。

### 4.1 努力必须可见

系统不仅保存完成结果，也保存投入时间、专注次数、困难、失败记录和下一步。任务延期、取消或归档不能抹掉已经发生的努力。

### 4.2 进度必须真实

任务数量不能直接代表工作量。系统需要区分等权进度、工作量进度、执行进度和掌握度，并允许里程碑使用不同权重。

### 4.3 数据必须属于用户

业务数据库、附件、证据、备份、导出和回收站都位于用户选择的根目录。工作区使用相对路径，复制后仍可打开。

### 4.4 功能必须形成闭环

计划、任务、计时、成果和复盘之间必须能够互相转换和关联。v1 不接受“多个独立小工具放在同一窗口”的实现。

### 4.5 复杂度必须可控

默认界面突出今天、近期风险和真实投入。高级字段按需展开，避免用户为了维护系统而停止实际行动。

## 5. 目标用户与使用场景

有迹面向单机个人用户，但同一套模型需要适应不同领域。

### 5.1 学习一门课程

用户选择一本官方教材，将章节建立为里程碑，把阅读、笔记、习题、测试和复盘作为任务。系统同时显示章节等权进度、工作量进度、掌握度和考试倒计时。

### 5.2 开发一个程序

用户以版本或功能作为里程碑，记录设计、实现、测试和发布任务。代码、构建产物和测试结果作为成果证据，与努力记录关联。

### 5.3 健身与习惯

用户同时使用一次性任务、周期习惯和数值指标。例如“购买跑鞋”是任务，“每周跑步三次”是习惯，“季度累计 100 公里”是指标。

### 5.4 阅读一本书

用户以章节或页数作为里程碑，记录阅读时间、读书笔记、疑问和复习计划，并通过标签聚合同主题的多本书。

### 5.5 一般个人项目

用户可以快速建立目标、里程碑和任务，在日历中安排时间，通过倒计时管理期限，并在每日或每周复盘中调整计划。

## 7. 明确不在 v1 范围内

下面的能力不属于第一版，不能作为隐藏依赖进入架构。

- AI 自动拆分任务、生成计划、总结复盘或预测风险。
- 云端账户、云同步和浏览器网页版。
- 多人空间、分工、评论、审批和社交排名。
- 第三方插件市场和公开扩展协议。
- macOS、Linux、Android 和 iOS 客户端。
- 简体中文以外的界面语言和运行时语言切换。
- 在线课程购买、内容推荐和教材版权内容分发。

## 8. 核心用户流程

这些流程必须在真实 Electron 程序中端到端可完成。

### 8.1 首次启动并创建工作区

用户首次启动时需要明确选择数据位置。

1. 程序显示“创建新工作区”和“打开已有工作区”。
2. 用户选择一个有写入权限的文件夹。
3. 程序验证目录、创建工作区标记和数据库。
4. 程序显示工作区路径、备份说明和初始模板入口。
5. 用户进入空白首页或选择模板创建第一个项目。

### 8.2 使用官方教材建立课程

课程流程需要同时支持结构化计划和真实学习记录。

1. 用户创建课程项目并填写教材信息。
2. 用户手动添加章节，或从纯文本目录批量创建章节。
3. 系统把每个章节建立为里程碑。
4. 用户为章节添加阅读、笔记、习题、测试和复盘任务。
5. 用户选择等权进度或工作量进度作为主显示模式。
6. 用户执行任务并记录时间、难度、笔记和成果证据。
7. 系统分别更新执行进度、掌握度和课程总体进度。
8. 系统根据考试日期显示所需学习速度和风险。

### 8.3 快速记录并转化行动

备忘录必须能够进入执行闭环。

1. 用户从任意页面打开快速记录。
2. 用户输入文本并可添加标签、附件或关联项目。
3. 内容先进入备忘收件箱，不强制分类。
4. 用户稍后把备忘转换为任务、知识点、错题或普通笔记。
5. 转换后保留原始创建时间和来源关系。

### 8.4 记录一次真实努力

努力记录需要独立于任务完成状态。

1. 用户从任务启动计时，或手动补录一次投入。
2. 用户可以记录中断、困难和实际结果。
3. 停止后，系统保存时间段、关联对象和标签。
4. 用户可以添加成果证据并设置下一步。
5. 即使任务后来取消，努力记录仍保留在账本中。

### 8.5 每周复盘并调整计划

复盘必须能直接修改后续计划，但不能重写历史事实。

1. 系统汇总计划与实际时间、完成情况、延期原因和成果。
2. 用户填写本周成果、问题和下周重点。
3. 用户批量顺延、拆分、取消或重新安排未完成任务。
4. 系统保留调整前后的日期和原因。
5. 新计划进入下周视图，历史努力和原计划保持可追溯。

### 8.6 迁移工作区

迁移必须在失败时保护原数据。

1. 用户在设置中选择“迁移当前工作区”。
2. 程序检查目标目录、剩余空间和写入权限。
3. 程序关闭业务写入并建立迁移状态。
4. 程序复制、校验并尝试打开新工作区。
5. 验证成功后，程序切换到新根目录。
6. 原目录保留，不自动删除或合并。

## 9. 关键业务规则

这些规则是功能正确性的最低约束，详细逻辑见 [领域模型与逻辑关系](03-领域模型与逻辑关系.md)。

- 难度、优先级、预计时间和紧迫度是四个独立属性。
- 任务难度使用 1 至 5 级，但难度不直接决定完成进度。
- 等权进度按纳入计算的里程碑数量计算。
- 工作量进度按预计工作量或手动权重计算。
- 执行进度和掌握度独立展示，不能互相覆盖。
- 任务完成不自动代表成果已经验证。
- 删除任务采用软删除，不能级联删除努力记录和成果证据。
- 所有主要业务对象都可以没有标签，也可以拥有多个标签。
- 附件导入后复制到工作区，数据库只保存相对路径。
- 复盘可以调整未来计划，但不能篡改已经发生的努力记录。

## 10. 首页信息目标

首页需要在一个屏幕内优先回答“今天做什么”和“当前是否有风险”。

- 最近的三个重要倒计时。
- 今日最重要的一件事和最多三个重点任务。
- 今日时间轴和当前正在进行的任务。
- 本周真实投入曲线。
- 当前项目进度与风险。
- 快速备忘入口。

首页可以由用户调整模块顺序和显隐，但核心信息必须有默认布局。

## 11. 非功能要求

v1 的质量要求与功能范围同等重要。

### 11.1 本地与离线

程序在断网状态下必须完成全部核心功能。启动、查询、编辑、计时、提醒、备份和恢复不能依赖远程服务。

### 11.2 数据安全

程序必须提供事务写入、异常恢复、软删除、自动备份、手动备份、恢复预检和工作区完整性检查。详细要求见 [工作区与数据安全](05-工作区与数据安全.md)。

### 11.3 性能目标

在参考数据规模下，常用操作应保持即时反馈。

| 场景 | 目标 |
|---|---|
| 冷启动到可操作首页 | 3 秒内，参考 Windows 设备上测量 |
| 普通列表首次显示 | 500 毫秒内 |
| 创建或更新普通对象 | 300 毫秒内显示成功结果 |
| 10,000 个任务的组合筛选 | 1 秒内返回首屏 |
| 20,000 个任务和备忘的全文搜索 | 1 秒内返回首屏 |
| 100,000 条努力记录的月度汇总 | 2 秒内完成或显示可见进度 |
| 自动保存 | 用户停止输入后 1 秒内落盘 |

这些数字是验收目标，不是当前已验证性能。

### 11.4 可访问性与交互

主要流程以 WCAG 2.2 AA 作为界面基线。普通文本对比度不低于 4.5:1，大文本和图形控件不低于 3:1；界面放大到 200% 时，核心功能仍可操作。

创建任务、开始或停止计时、保存备忘、搜索、选择标签和操作对话框必须支持纯键盘完成。颜色不能成为状态和风险的唯一表达方式，核心流程需要使用 Windows Narrator 检查名称、角色、状态和焦点顺序。

### 11.5 Windows 集成

程序需要提供 Windows 安装版和便携版，支持系统通知、文件夹选择、在资源管理器中打开工作区和单实例运行。

主窗口不显示原生 Windows 标题栏和边框，使用不透明的自绘标题栏、拖动区和最小化、最大化、还原、关闭按钮。文件夹选择和消息确认仍可使用系统原生对话框。

关闭主窗口默认隐藏到系统托盘，使计时和提醒继续运行；托盘明确提供“打开有迹”和“退出”。用户可以在设置中改为关闭即退出。明确退出前需要提示后台计时和提醒将停止，下一次启动时重新计算并汇总错过的提醒。

### 11.6 安全边界

渲染层不能直接访问 Node.js、数据库和任意文件系统。所有高权限操作通过受控、校验后的 Electron IPC 完成。

## 12. 成功标准

v1 成功不以功能入口数量衡量，而以用户能否持续完成闭环衡量。

- 用户可以在 10 分钟内创建工作区和第一个课程或项目。
- 用户可以在不阅读数据库结构的情况下完成备份与迁移。
- 用户可以查看任一目标的投入、成果、进度、掌握度和期限风险。
- 用户可以通过标签聚合来自任务、倒计时、备忘和努力记录的内容。
- 用户可以恢复误删内容和最近的有效备份。
- 程序重启、异常退出和根目录暂时不可用时不静默丢失数据。

## 13. v1 发布边界

只有 [v1 验收标准](06-v1验收标准.md) 的发布门槛全部满足，版本才能从 `PREPARED` 进入 `VERIFIED`。

必须同时满足：

- 全部 FR-01 至 FR-23 有真实实现和对应验收证据。
- 安装版和便携版在干净 Windows 环境完成实际启动检查。
- 创建、记录、备份、恢复和迁移流程完成真实 Electron 端到端测试。
- 工作区中断、磁盘只读、空间不足和数据库异常有明确可恢复行为。
- 文档、界面术语、数据结构和测试用例不存在已知冲突。
